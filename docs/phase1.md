# Phase 0 & 1 — Bring-up and Baselines

Notes for the first two phases of [`plan.md`](../plan.md): environment setup,
the vendored simulator build, and the SA / LS baseline sweep.

## Phase 0 — Environment and build

### Toolchain

The system packages (`scons`, `libconfig++-dev`) require root, which is not
available here, so both are built into a project-local prefix by
`scripts/setup-deps.sh`:

| Dependency | Location | How |
|---|---|---|
| SCons | `.deps/venv/` | `python3 -m venv` + `pip install scons` |
| libconfig++ 1.7.3 | `.deps/libconfig/` | built from source (`./configure && make && make install`) |

Both are git-ignored; `scripts/build.sh` drives the build.

### Upstream build fixes

The upstream README build steps do not work out of the box (matching the SOSP
artifact review note that the README is partially broken). Three minimal fixes
were needed in the vendored tree under `third_party/Kangaroo`:

1. **Missing `simulator/lib/SConscript`.** Upstream `simulator/SConscript`
   calls `env.SConscript('lib/SConscript', ...)`, but no such file exists in the
   repository (`lib/` contains only headers). Added a no-op `lib/SConscript`.
2. **`libconfig++` discovery.** Command-line and `site_scons` overrides were not
   honoured by the unmodified SConstruct, so `simulator/SConstruct` now reads
   `LIBCFG_INCLUDE` / `LIBCFG_LIB` and appends them to `CPPPATH` / `LIBPATH`.
3. **Missing `<cstdint>` (toolchain portability).** The legacy sources use
   `uint64_t` / `uint32_t` without including `<cstdint>`; older toolchains pulled
   it in transitively, modern g++ 13 does not. Fixed with a force-include of
   `cstdint` in `CPPFLAGS` rather than editing many headers.

Additionally the binary is linked with `-Wl,-rpath=<libconfig>/lib` so it runs
without `LD_LIBRARY_PATH`.

### Verification

- `scripts/build.sh` completes with exit code 0 and produces
  `third_party/Kangaroo/simulator/bin/cache` (~11.8 MB).
- The binary prints its usage banner when invoked with no arguments and loads
  without `LD_LIBRARY_PATH` (rpath confirmed).

## Phase 1 — SA / LS baselines

### Workload and sweep

Configuration generated by the upstream `run-scripts/genConfigs.py` and saved in
`configs/baselines/` (30 configs):

- **Trace:** Zipf, `alpha = 0.9`, 1 000 000 objects, ~10.24 M requests.
- **DRAM:** {1, 2, 3, 5, 10} MB; **flash:** {10, 20, 50} MB.
- **SA** (`memoryCache` + `sets`, no log): set-associative baseline.
- **LS** (`memoryCache` + `log`, no sets): log-structured baseline.

Each config is run by `scripts/run-baselines.sh`; the last summary line printed
by the simulator (steady state, post-warm-up) is parsed by
`scripts/collect.py` into `results/baselines/baseline_results.csv`.

### Results

Miss ratio and application-level write amplification (WAF). WAF is constant per
design on this workload: **SA = 64** (a full 4 KB page written per ~64 B object),
**LS = 1.0** (sequential log writes). Sample (flash = 20 MB):

| Design | DRAM 1 MB | 2 MB | 3 MB | 5 MB | 10 MB | WAF |
|---|---|---|---|---|---|---|
| SA | 0.2421 | 0.2333 | 0.2247 | 0.2087 | 0.1746 | 64.0 |
| LS | 0.2463 | 0.2374 | 0.2286 | 0.2124 | 0.1774 | 1.0 |

Full sweep: `results/baselines/baseline_results.csv`.

### Checks performed

- **Build:** exit 0; binary produced and runnable. ✅
- **Both code paths exercised:** SA resolves to `SetOnlyCache`, LS to
  `MemLogCache` (confirmed via the generated configs' `sets` / `log` blocks). ✅
- **Write amplification sanity:** LS alwa ≈ 1 (log-structured), SA alwa ≫ 1
  (set rewrite). ✅
- **Monotonicity:** miss ratio decreases as DRAM grows, for every design and
  flash size. ✅
- **Accounting:** SA and LS miss ratios are of the same order at matched budgets;
  SA is marginally lower (it uses the full flash as set capacity, whereas LS
  exhibits the paper's DRAM-index limit). ✅

### Observations / notes for later phases

- These runs are **capacity-only**: no device write-rate budget is imposed, so
  SA is not throttled despite its 64× WAF. The paper's headline comparison
  (Kangaroo beats both under a write budget) is reproduced in Phase 7.
- The simulator prints `Flash Write Amp` from each cache's
  `calcFlashWriteAmp()`; Kangaroo (Phase 5–6) adds the log + set terms and the
  admission `byteRatioAdmitted()` scaling.
